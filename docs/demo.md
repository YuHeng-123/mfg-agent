## 场景 1 · 正常故障处置（设备域）

**问题**：`3 号线空压机报 E05，排气温度 118℃，怎么处理？`

```
1. 现象：排气温度显示超过 105 ℃ 报警，超过 115 ℃ 机组联锁停机。（5.3 故障代码 E05 排气温度过高）
2. 处置步骤： 1. 立即将机组降载至 70% 以下，确认冷却水阀开度与循环水流量开关状态。（5.3 故障代码 E05 排气温度过高）
3. 当前实测：温度 122.5℃（阈值 105℃，超标）；振动 4.94mm/s（阈值 4.5mm/s，超标）；电流 101.8A，已与设备档案阈值比对。
4. 同故障码历史工单 3 条，最近一条处置为「恢复冷却水流量后复测进出水温差｜5.4 h｜已解决」。
```

**看什么**：每条结论后面都带章节号和页码；第 3 条是传感器实测，不是手册里的数字；第 4 条是历史工单。
**服务端耗时**：34 ms（`elapsed_ms` 字段）。
**截图位置**：① 对话区这条回答，② 右侧证据面板里 10 条引用（3 本手册段落 + 3 张工单 + 1 条实时读数）。

## 场景 2 · 型号混淆陷阱（不写型号会怎样）

**问题**：`空压机安全阀多久校验一次`

```
1. 安全阀校验 ｜ 每年 ｜ 须有校验报告（6.1 维护周期）
```

引用命中（5 条）：`AX300 使用与维护手册 p5 / p2 / p3`、`AX310 使用与维护手册 p2`。

**看什么**：库里有 4 本手册（两台空压机、一台泵、一台换热器）。问题没写型号，
检索退到**机型族**（"空压机" → AX300 + AX310），所以引用只落在空压机两本上，
换热器手册和泵手册一次都没出现。这就是型号过滤的作用——早期版本这里会引用到换热器手册。

**截图位置**：右侧证据面板，5 张卡片的手册名只有 AX300/AX310。

## 场景 3 · 证据不足拒答（能答但不该答）

**问题**：`这台泵的轴承型号是多少？`

```
（answer 为空）
refusal:
  kind: insufficient_evidence
  reason: 关键内容覆盖不足（命中词 1 个 / 阈值 3，信息量 1.4495 / 阈值 2.5）
  missing: [知识库未收录该问题的关键内容（型号、规格或部件信息）]
  action: 建议查设备铭牌、订货资料或转设备科确认
```

**看什么**：这个问题的关键点是"拒答**说清了缺什么**"。它检索到了 5 段（型号过滤=BP2200 生效了），
但证据闸判定覆盖不足，于是不给答案。对比场景 3 与场景 1：有料的答，没料的说清缺什么。

**截图位置**：对话区的橙色拒答块（左上角标签写着 `insufficient_evidence`）。

## 场景 4 · 安全拦截（连库都不查）

**问题**：`带电拆开接线盒检查`

```
该问题须由持证人员处理：电气作业须停电、验电、挂牌上锁（LOTO）后由持证电工执行。

refusal:
  kind: safety_blocked
  reason: 命中安全规则 E-SAFE-01：电气作业须停电、验电、挂牌上锁（LOTO）后由持证电工执行
  action: 转人工
```

**看什么**：trace 只有一行 `安全规则 E-SAFE-01 命中，短路`——**没有检索、没有调模型**。
这和场景 3 是两类拒答：一个是"不让答"，一个是"不会答"。混在一起就说不清系统的边界在哪。

**截图位置**：对话区红色拒答块 + 右侧证据面板为空（因为没有检索）。

## 场景 5 · 文件换版体检（第二条业务线，同一个核）

**问题**：`对照新版 7.1.6 组织知识，我们质量手册要改哪几处？`（切到"文件体检"）

```
1. G-01（7.1.6-a）质量手册 §4.2.3 只写了经验积累，未规定知识的来源与更新方式
2. G-02（7.1.6-b）培训教材 §3 未覆盖经验流失风险及应对措施
3. G-06（7.1.6）厂内未收录《组织知识管理程序》，条款整体无对应程序文件
```

每条差距挂两个引用：条款原文（`GB19001-2026_excerpt#s05#c01`）+ 受影响文件的那一节
（`quality_manual#s02#c01` / `training_material#s01#c01`）。

**看什么**：差距识别**不经过模型**——7 条条款要求 → 子串覆盖检查 → 没覆盖就是差距。
所以评审问"你凭什么说这文件缺了"，答案是"这 5 份厂内文件里没有任何一份同时出现『知识』『来源』『更新』"，
十秒能验证。模型只负责把结论写成句子。

**截图位置**：① 右侧领域切换按钮在"文件体检"，② 三步差距清单，③ 证据面板里标准条款卡片。

## 场景 6（加分）· 多跳：一句话问三件事

**问题**：`AX300 报 E05 处置步骤是什么，事后按什么周期点检，备件型号是什么`

```
1. 处置步骤： 1. 立即将机组降载至 70% 以下，确认冷却水阀开度与循环水流量开关状态。（5.3 故障代码 E05 排气温度过高）
2. 现象：排气温度显示超过 105 ℃ 报警，超过 115 ℃ 机组联锁停机。（5.3 故障代码 E05 排气温度过高）
3. 空气滤芯 ｜ 压差 0.15 MPa 或 2000 h ｜ 以先到为准（6.1 维护周期）
```

**看什么，也要说清它的短板**：这句问了三件事（处置 / 点检周期 / 备件型号），
系统按标点切成子句分别检索，引到了 §5.3 处置、§6.1 维护周期；**备件清单（§6.2）进了候选但没进结论**。
多跳覆盖率只有 58.3%（单跳 84.0%），这就是那 26 个点的具体样子——**演示时主动说出来，别等被问**。

**截图位置**：证据面板里同时出现 `p3`、`p4`、`p5` 三个页码的段落。

## 复现全部场景

```bash
VP=~/.workbuddy/binaries/python/envs/default/Scripts/python.exe
$VP -m uvicorn app.main:app --host 127.0.0.1 --port 8321

# 场景 1
curl -s --noproxy '*' -X POST http://127.0.0.1:8321/api/ask \
  -H 'Content-Type: application/json' \
  -d '{"domain":"equipment","query":"3 号线空压机报 E05，排气温度 118℃，怎么处理？"}'

# 场景 2 / 3 / 4 只换 query
# 场景 5 换 domain 为 compliance
```

> `--noproxy '*'` 是这台机器的必需参数：系统代理会把 127.0.0.1 也代理掉，导致 curl 报
> `upstream connect failed`。浏览器访问不受影响。

也可以不开服务，直接跑断言的版本：

```bash
$VP -m pytest -q          # 64+ 条，覆盖上面每个场景的判定
```

## 讲的时候的取舍

- 前 3 分钟只讲场景 1 → 3 → 4：**能答、答不了、不让答**，三个状态三句话讲完。
- 场景 2 是给"你们怎么防串型号"这类追问准备的。
- 场景 5 用来证明"核心是复用的，不是为一个场景定制的"。
- 场景 6 主动交代短板，比被问出来强。
