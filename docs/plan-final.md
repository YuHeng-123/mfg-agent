## 1. 一句话

**一个企业知识库，挂两种用法：现场问它（设备运维），换版查它（文件体检）。**

```
                 ┌──────────────────────────┐
                 │   core/  能力层（领域无关） │
                 │  检索 · 编排 · 引用 · 拒答  │
                 └────────┬─────────┬───────┘
                          │         │
        ┌─────────────────▼──┐   ┌──▼──────────────────┐
        │ domains/equipment  │   │ domains/compliance  │
        │ 知识的【取用】      │   │ 知识的【体检】       │
        │ 设备坏了怎么修      │   │ 新标准来了该改哪     │
        └────────────────────┘   └─────────────────────┘
```

**这就是"企业知识库"**——但不是问答机器人。问答机器人只有一个动作（问→答）；这个有两个动作（取用、体检），而且两个动作共用同一套检索、引用、拒答、trace、评测。

---

## 2. 为什么是这两个场景

| | 取用（设备运维） | 体检（标准换版） |
|---|---|---|
| 用户 | 维修工 | 质量部 / 体系负责人 |
| 真实痛点 | 手册太厚，现场翻不动 | ISO 9001:2026 换版窗口（2026–2028），要逐条核对自家文件，全靠人肉 |
| 交付物 | 带出处的处置步骤 + 工单草稿 | 差距清单：哪几处要改、引哪条新条款、缺哪份文件 |
| 出错代价 | 多修几小时 | 证书保不住 |
| 评测方式 | Recall@k + 引用精确率 | 差距清单逐条核对（客观） |

两个场景的本质是同一件事：**知识在正确的时候被正确地取出来，并且能追到原文。**

一句能背下来的项目定位：

> 「我做的是企业知识的两个动作：取用和体检。取用解决'现场问什么答不出'，体检解决'文件早就过期了没人发现'。」

## 3. 架构与硬规则

```
core/                     不允许出现任何领域名词（泵/试剂/标准号）
├ rag/{loader,index,filters}
├ agent/{loop,tools,providers,prompts}
├ guard/{safety,evidence,citation}
├ evals/{metrics,runner,report}
└ observability/trace

domains/equipment/        loader · tools · safety_rules · entity_patterns · eval_items
domains/compliance/       同上

app/  main.py, api/routes.py
web/  index.html（领域切换器在左上角）
data/equipment/  data/compliance/
evals/  equipment.jsonl  compliance.jsonl  run.py  reports/
tests/  ≥20
```

**硬规则**

1. `core/` 里出现 `if domain ==` 或领域名词 → 算 bug，重构
2. 所有工具返回值必带 `citations`，生成后由 `guard/citation.py` 逐条核对能否在索引中查到，查不到整条降级
3. 接第二个领域时改 `core/` 超过 3 处 → 判定抽象失败，停下重构，不许打补丁

## 4. 七个工具

| 域 | 工具 | 说明 |
|---|---|---|
| 设备 | `search_manual` | 必须先锁型号再检索（型号硬过滤） |
| 设备 | `get_ticket_history` | 同故障码 Top3，带用时与结果 |
| 设备 | `get_device_state` | 档案 + 传感器读数，阈值来自档案 |
| 设备 | `create_ticket_draft` | 写操作，人工确认才落库 |
| 体检 | `search_standard` | 新标准条款检索，返回条款号 |
| 体检 | `search_internal_doc` | 厂内文件检索，返回文件名 + 章节 |
| 体检 | `record_gap` | 写操作：写入一条差距项（含条款引用） |

工具总数 7 个，但每个域只需记 4 个和 3 个——演示时不会乱。

## 5. 两类拒答（跨域统一实现）

| | `safety_blocked` | `insufficient_evidence` |
|---|---|---|
| 设备域 | 带电拆检、带压拆管、防爆区动火 | 手册未收录的型号/零件号 |
| 体检域 | （少用） | 工厂根本没这份文件 → **「我们缺这份文件」，这是差距分析里最值钱的输出** |
| 执行 | 规则命中即短路，不查库不调模型 | 查了，说清查到什么、缺什么 |

## 6. 数据（全部合成或公开资料，README 首屏标注）

| 数据 | 规模 |
|---|---|
| 设备手册 | 3 本（1 本真实公开手册 + 2 本自制，含故障码表与安全警告） |

| 差距样本 | 20 组（人工标注每份该改几处、缺哪份） |

## 7. 评测（一套脚本，两张表 + 跨域汇总）

| 域 | 样本 | 指标 |
|---|---|---|

## 8. 排期

| 时段 | 内容 | 完成标志 |
|---|---|---|
| 今晚 1（40min） | P0 探针：真实 PDF 能否抽出干净页码 + 章节标题 | 脚本 + 结论 |
| 今晚 2（1h） | 定 Domain 协议 + ToolResult/Citation + 骨架 | 两个假域能 import |
| 今晚 3（2h） | core + 设备域最小闭环（2 工具） | stub 下一次提问返回带引用答复 |
| 明天上午（3h） | 设备域补完 4 工具 + 型号过滤 + 两闸 + 30 条评测 | `evals --domain equipment` 出真数字 |
| 明天下午（3h） | 体检域接入 | `evals --domain compliance` 跑通 |
| 明天晚（3h） | 单页 + 工单三态 + 跨域汇总 | 浏览器可切换领域演示 |
| 后天 | 只修 bug、README、失败案例、录演示 | pytest ≥20 绿 |

**止损**：体检域超 4 小时 → 砍到只做"有差距/无差距"二分类 + 条款引用；超时先砍前端，再砍工单写操作，**不砍评测**。

## 9. 三分钟演示

1. `0:00` 「3 号线空压机报 E05，排气 118℃」→ 三条带出处处置 + 工单草稿
2. `0:50` 「这台泵的轴承型号？」→ `insufficient_evidence`
3. `1:10` 「带电拆开接线盒检查」→ `safety_blocked`，不查库
4. `1:40` 切到「体检」，选新标准章节 → 输出「5 处需修改 + 缺 2 份文件」，每处引条款
5. `2:20` 终端看行数：「换这个领域我写了 320 行，core 一行没改」
6. `2:40` 「工业场景里答错比不答贵得多。我做的不是让它会答，是让它的每句话能追到条款，追不到就不说；而且这套东西换个用法只要一天。」

## 10. 不做什么（写在 README，防止被问）

- 不做微调 / 预训练
- 不做工业视觉 / 质检图像
- 不接 Modbus / OPC-UA / MES / ERP（只留接口契约）
- 不做预测性维护
- 不做权限、多租户、并发压测
- 不做前端大屏、3D、动画
- 差距分析只做 1 个标准章节，不做全文、不做多体系
