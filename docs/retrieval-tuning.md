## 为什么第 2、3 条无效

**低信息章节的 section 权重不起作用**：`1.1 适用范围` 抢分靠的是 body 字段——它同时写了型号、设备全称、同系列对比，几乎覆盖提问里所有设备类词。而它的 section 字段（"1.1 适用范围"）本身命中率是 0。降一个本来就是 0 的分项，当然没效果。

得分构成实测（问「HE800 板式换热器外漏怎么补紧」）：

```
27.53  body=18.06  sec=0.00  title=6.31   1.1 适用范围      ← 错
21.09  body= 5.18  sec=3.58  title=6.31   4.4 故障代码 H03  ← 对
```

**title 权重也不起作用**：同一本手册里所有段落的 title 得分完全一样（都是 6.31），它是一个常量偏移，对排序没有任何区分度。型号过滤已经把文档选定了，title 是重复信号。

这两条都是"看起来该有用但实测没用"的改动。写在这里，比删掉更有价值——说明我是在测，不是在猜。

## 为什么最终只留 penalty

切分（按型号分层，2/3 训练 17 条、1/3 测试 8 条）后重新对比：

| 配置 | 训练 R@1 | 训练 Hit@1 | 训练 R@5 |
|---|---|---|---|
| drop_title=False, penalty=1.0 | 70.6% | 76.5% | 94.1% |
| **drop_title=False, penalty=0.5** | **76.5%** | **82.4%** | 94.1% |
| drop_title=True, penalty=1.0 | 73.5% | 76.5% | 100% |
| drop_title=True, penalty=0.5 | 73.5% | 76.5% | 100% |

**去掉标题词这个改动，在全量上看是 +6 分，在训练集上是负收益。** 这就是"在测试集上调参"的典型症状——全量数据被我看了三遍，它已经不算测试集了。

所以最终只上 `low_info_penalty = 0.5`（低信息段落总分打五折），`drop_title_terms` 默认为关，但代码保留，留给语料变大后再验。

选定的配置在测试集上（只跑这一次）：

```
Recall@1 87.5%   Hit@1 100%   Recall@5 100%   MRR 1.000
```

> 注意：测试集只有 8 条，这个数字**不可单独引用**。它只说明"方向对"，不说明"水平就是这个"。对外只报全量的 80%。

## 新增的两个指标

原来只报 Recall@k（集合召回）。但有些题 gold 有两个可接受段落，命中一个时集合召回只给 0.5 分——会低估。

所以加了 **Hit@1 / Hit@3**（命中任一可接受段落即为 1）。两个数一起看：

```
Recall@1 80.0%   Hit@1 88.0%   ← 差 8 个点，全部来自"多答案题"和"gold 跨页被拆成两块"
```

这个差值本身就是信息：它说明还有一部分题目，答案在库里但被判成半分。要么继续修切分，要么在标注上把同段跨页合并——这是下一轮的事。

## 结论

- 68% → 80%，其中 **4 个点来自修正标注**（不是检索改进），**8 个点来自低信息段落降权**
- 两次"看起来该有用"的改动（section 权重、title 权重）实测无效，已记录
- 一次"全量有效、训练集无效"的改动（去掉标题词）被切分拦下来了，没上
- 失败案例仍保留 5 条，其中 1 条（E-25 同词不同义）不打算修，写进 README 当边界说明
