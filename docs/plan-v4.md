# 设备运维 Agent · 双领域版执行方案 v4

> 本文取代 `plan.md`（v2，真实手册线）与 `plan-v3.md`（v3，单领域合并版）。
> 变化：从「一个领域做深」改为「一套 core + 两个领域」，是**一个大项目**，不是两个小项目。

---

## 0. 一句话

**一套 Agent 能力层（检索 / 编排 / 双闸拒答 / 引用校验 / trace / 评测），挂两个工业领域：设备运维 与 危化品储存应急。换领域只写领域包，core 一行不改。**

---

## 1. 为什么这是"一个大项目"

判断标准不是"代码放几个仓库"，而是**第二块能力是不是复用了第一块**。

| | 两个平行项目 | 本文的做法 |
|---|---|---|
| 代码关系 | 复制粘贴，各跑各的 | core 共享，领域层只写差异部分 |
| 评测 | 两套口径，两套脚本 | 一套 `evals/run.py`，两个 domain 各一张表 + 一张跨域汇总 |
| 拒答 | 各写各的，逻辑会漂移 | core 里统一实现，领域只提供规则和阈值 |
| 简历怎么写 | "我做了两个 demo" | "我做了一套可插拔的工业 Agent 框架，两个领域复用率 XX%" |
| 面试追问 | 问哪个就答哪个 | 问"你怎么保证两个领域行为一致"——这正是核心考点 |

**可量化的论据（必须真实统计后填）**：

```
core 行数        ≈ 1700
domain A 行数    ≈ 380   (设备运维：loader + 2 工具 + 14 条安全规则 + 30 条评测)
domain B 行数    ≈ 320   (危化品：loader + 2 工具 + 相容性矩阵 + 20 条评测)
core 复用率      ≈ 71%
```

这个数字比任何形容词都有说服力。

## 3. Domain 协议（今晚第一件事就是把它钉死）

```python
class Domain(Protocol):
    name: str
    def load_chunks(self) -> list[Chunk]              # 必须带 doc_id / page / section
    def tools(self) -> dict[str, Tool]                # 领域专属工具
    def safety_rules(self) -> list[SafetyRule]        # 正则 + 关键词，命中即短路
    def entity_patterns(self) -> dict[str, Pattern]   # 用于"未登录实体"检测
    def eval_items(self) -> list[EvalItem]
    def prompt_profile(self) -> PromptProfile         # 术语表 + 输出格式约束
```

工具返回值统一带引用，**这是让"不许编"成为类型约束而不是口头承诺**：

```python
@dataclass
class ToolResult:
    data: dict
    citations: list[Citation]   # 空列表 = 该工具没提供证据

@dataclass
class Citation:
    doc_id: str
    page: int | None
    section: str | None
    snippet: str
    kind: Literal["manual", "ticket", "sensor", "msds", "rule"]
```

`guard/citation.py` 在生成后逐条核对：每个结论的 citation 必须能在索引里查到、且属于当前领域。查不到 → 整条降级为「低置信」。领域层**没有能力**绕过这一关。

## 4. 领域 A：设备运维（主战场，占 60% 精力）

- 3 本手册（1 真 2 自制）+ 6 台设备档案 + 300 条工单 + 3 台传感器
- **型号硬过滤**：先锁 AX300，再在该型号手册里检索；报告里给开/关过滤的 A/B 数字
- 工具：`search_manual` / `get_ticket_history` / `get_device_state` / `create_ticket_draft`
- 安全规则：高压、带电、拆机、燃气、高温带压拆检、防爆区作业
- 演示三连：E05 带出处处置 → 轴承型号拒答 → 带电拆检拦截

## 5. 领域 B：危化品储存与应急（第二张皮，占 25%）

**只做三件事，多一件都不做**：

1. **相容性判断**：「这两种试剂能否同柜存放」→ GHS 分类矩阵（氧化剂×还原剂、酸×碱、遇水放热×水基…），**确定性规则，不经过模型**，附 MSDS 原文段落
2. **MSDS 检索**：闪点、储存条件、个体防护、泄漏处置，带 doc/段落引用
3. **泄漏应急处置**：进入安全闸分支——「大量泄漏且无防护装备」直接短路转应急流程

明确不做：库存台账、法规全文检索、化学品计量、配方管理。

**它的真正作用不是功能，是证明 core 抽象对了。** 演示时只说一句话：「这套东西换一个领域，我写了 320 行。」

## 6. 两类拒答（跨领域统一）

| | `safety_blocked` | `insufficient_evidence` |
|---|---|---|
| 设备域 | 带电拆检、带压拆管、防爆区动火 | 手册未收录的型号/零件号 |
| 危化品域 | 无防护处置大量泄漏、混放高危组合 | MSDS 未收录的 CAS 号 |
| 执行 | 规则命中即短路，不查库不调模型 | 查了，说清查到什么、缺什么 |
| 指标 | 拦截率 + **误拦截率** | 正确率 + **误拒率** |

两个领域的规则表分别写在 `domains/*/safety.py`，但执行逻辑、短路时机、trace 记录全在 `core/guard/safety.py` —— 这是"行为一致"的保证。

## 7. 评测（一套脚本，两张表 + 一张汇总）

| 域 | 样本 | 指标 |
|---|---|---|
| 设备 | 30（故障码 10 / 操作步骤 8 / 参数含义 5 / 应拒 7） | Recall@1/3/5、MRR、引用精确率、拒答矩阵、型号过滤 A/B |
| 危化品 | 20（相容性 8 / MSDS 检索 6 / 应急 3 / 应拒 3） | 相容性判断准确率 + **规则未覆盖组合数**、引用精确率、拒答矩阵 |
| 跨域 | — | **core 复用率**、domain B 新增行数、两域共用测试通过数、两域延迟对比 |

相容性指标特别说明：这是确定性规则，准确率 100% 没什么可吹，**真正该报的是"规则矩阵覆盖了多少组合、剩下多少落到检索兜底"**——这才是工程判断力。

## 9. 排期与止损（现在 → 后天）

| 时段 | 干什么 | 完成标志 |
|---|---|---|
| **今晚 1（0.5h）** | P0 风险探针：真实 PDF 能否抽出干净页码 + 章节标题 | 一个能跑的脚本 + 结论，决定真实手册线还是自制线 |
| **今晚 2（1h）** | 钉死 Domain 协议 + ToolResult/Citation 数据结构 + 目录骨架 | 协议文件写完，两个领域都能 Fake 出空实现并 import 成功 |
| **今晚 3（2h）** | core 骨架 + 设备域最小闭环（只 2 个工具）+ `/healthz` | stub 下一次提问能返回带引用的答复 |
| **明天上午（3h）** | 设备域补完：4 工具、型号过滤、两闸、trace、30 条评测 | `evals --domain equipment` 出真数字 |
| **明天下午（3h）** | 接入危化品域 | `evals --domain chemical` 能跑通 |
| **明天晚上（3h）** | 单页 + 工单三态 + 跨域汇总报告 | 浏览器里能切换领域并演示 |
| **后天（留白）** | 只修 bug、补 README、失败案例、录演示 | pytest ≥20 绿 |

### 止损规则（比排期更重要）

1. **接危化品域时，如果需要改 `core/` 超过 3 处** → 判定抽象失败，停下来重构 core，不许在 core 里写领域分支。
2. **危化品域超过 4 小时没跑通** → 砍到只做"相容性判断"一件事，其余标 TODO。
3. **真实 PDF 抽不干净** → 全自制 PDF，README 写明未处理扫描件。
4. **任何阶段超时** → 先砍前端，再砍工单写操作，不砍评测。

## 10. 三分钟演示（双域版不能讲两条完整线）

**讲法：设备线讲完整链路，危化品线只讲一件事——换领域有多便宜。**

1. `0:00` 「3 号线空压机报 E05，排气 118℃」→ 带出处的处置 + 工单草稿
2. `0:50` 「这台泵的轴承型号？」→ `insufficient_evidence`
3. `1:10` 「带电拆开接线盒检查」→ `safety_blocked`，不查库不调模型
4. `1:40` 左上角切到「危化品」，问「甲醇和硝酸能放同一个柜子吗」→ 说出不相容类别 + MSDS 引用
5. `2:10` 打开终端：`git diff` 或代码行数统计——**「换这个领域，我写了 320 行，core 一行没改」**
6. `2:40` 「工业场景里答错比不答贵得多。我做的不只是让它会答，是让它的每句话能追到页码，追不到就不说；而且这套东西换个领域只要一天。」

## 11. 已知边界（写进 README）

- 工单、传感器、自制手册、MSDS 样本均为合成或公开资料整理，不含真实企业数据
- 相容性矩阵为教学用简化版，不可用于实际安全管理
- 未接入 MES / ERP / 设备网关；工单只到草稿态
- stub 模式答复为模板拼装，不代表模型能力
- 未做权限、多租户、并发压测
