## 0. 一句话

**按设备型号锁定手册范围检索证据，调用工具补实时参数，产出每条都挂出处（手册+页码+段落号）的处置建议；安全性问题与证据不足问题分别拒答，并给出转人工路径。**

## 1. v1 / v2 怎么合的

### 1.1 v2 独有的、v1 没有的（必须保留）

| 设计 | 为什么留 | 怎么加强 |
|---|---|---|
| **设备型号硬过滤** | v2 最有价值的一条。工业现场最容易出事的不是"没查到"，是"拿 A 型号的步骤套到 B 型号上" | 升级成**可量化 A/B 实验**：同一批问题，开/关过滤各跑一遍，报告里给"引用到错误型号手册的比例"。这是全项目最强的一个数字 |
| **安全护栏前置** | v1 只有"证据不足拒答"，没有"安全问题拦截"。这俩不是一回事 | 改成**确定性规则引擎**（关键词 + 正则 + 设备白名单），命中即短路，不走模型，不查库。可测拦截率 **和误拦截率** |
| **自动建单** | 制造业要的不是"能聊天"，是"能进流程" | **降级为草稿**：只做 `draft → confirmed → closed` 三态，不做 SLA 计算引擎，不做升级规则。AI 只写草稿，人点确认才入库 |
| **真实 PDF 手册** | 页码、表格、页眉页脚被切碎——这些坑讲得出来才叫干过 | **双轨**：1 本真实公开手册（证脏数据处理）+ 2 本自制手册（保证故障码全集覆盖率、可复现） |
| **极简单页前端** | v1 说不要前端，但演示脚本里"面板显示手册段落 2 处"靠 curl 撑不起来 | 只做一页：左侧对话，右侧证据面板（点引用高亮定位到原文），底部工单卡 |

### 1.2 v1 独有、v2 缺的（必须补回）

| 设计 | 为什么 v2 必须补 |
|---|---|
| **离线可跑（StubProvider）** | v2 全链路依赖 LLM + 向量模型。面试官一句"现场能跑吗"就死。有 stub，评测报告任何时候都能重跑出同样的数 |
| **证据性拒答（缺哪份资料）** | v2 只有安全拦截。知识库里没有的东西（"这台泵的轴承型号"）v2 会直接让 LLM 硬答 |
| **分层评测 + 混淆矩阵 + 误拒率** | v2 只有 Recall@5 和引用准确率，**没有应拒样本**，所以永远测不出"乱答"，也测不出"该答的被我拒了" |
| **trace（每步工具 / 耗时 / 命中文档）** | v2 有 observability 目录但没有指标定义 |
| **pytest ≥ 15** | 没有测试的项目，改一行就崩，也不敢给别人看 |

### 1.3 裁决掉的（两边都有，但都不要）

| 砍掉 | 原因 |
|---|---|
| "复用现有 Agent 运行时与 MCP 工具层"（v2） | 会把一个不属于本项目的复杂度绑进来，且是黑盒，讲不清。**自写 80 行工具循环**，白盒、可控、可讲 |
| "Recall@5 ≥ 0.85 / 引用准确率 ≥ 0.90" 这种既定目标值（v2） | 写死在方案里等于自我绑架：跑不到就只能改口径或注水，两条都踩红线。改成**实测后填 + 附 3 条失败案例**。面试里"我的 Recall@5 是 0.78，失败集中在跨章节多跳"比"0.87"可信十倍 |
| 微调 / 预训练 / 工业视觉 / PLC 对接 / 3D 大屏（v1） | 与岗位技术栈不符，且都做不成真的 |
| 传感器预测性维护（v2） | 没有真实时序数据，做出来是假的。保留传感器**只用于"查当前值发现异常"**，不做预测 |

## 2. 合并后架构

```
web/index.html            单页：对话 + 证据面板 + 工单卡（原生 JS，无构建）
app/
├── main.py               FastAPI 入口（/api/ask, /api/tickets, /healthz, /api/eval/latest）
├── api/routes.py
├── rag/
│   ├── loader.py         PDF/md → 章节切分，保留 page / section / chunk_id
│   ├── index.py          BM25(bigram) + 向量(可选) + RRF + 型号硬过滤
│   └── rerank.py         可选，缺失即降级
├── agent/
│   ├── loop.py           工具循环：max_steps=6，白名单，单步超时，每步 trace
│   ├── tools.py          4 个工具（见下）
│   └── providers.py      StubProvider / OpenAICompatProvider
├── guard/
│   ├── safety.py         高危规则 → safety_blocked
│   ├── evidence.py       检索分阈值 + 未登录实体 → insufficient_evidence
│   └── citation.py       生成后校验：每条结论必须挂到真实存在的 chunk_id
├── ticket/store.py       SQLite，三态
└── observability/trace.py
data/
├── manuals/              3 本（1 真实 + 2 自制）
├── registry/devices.json 设备档案：型号 / 产线 / 位置 / 手册映射
├── tickets/              300 条合成工单（含型号、故障码、处置、用时、结果）
└── sensors/              3 台 × 7 天 × 1min（含 3 段注入异常）
evals/
├── dataset.jsonl         30 条分层样本
├── run.py                控制台表 + JSON 报告
└── reports/
tests/                    ≥ 15 条
```

### 四个工具（3 读 + 1 写）

| 工具 | 作用 | 关键点 |
|---|---|---|
| `search_manual(query, model_id)` | 检索手册段落 | **model_id 是硬过滤参数**，先锁型号再检索 |
| `get_ticket_history(fault_code, model_id)` | 同故障码历史工单 Top3 | 返回处置动作 / 用时 / 结果，挂工单号 |
| `get_device_state(device_id)` | 设备档案 + 当前传感器读数 | 返回是否超阈值（阈值来自档案，不是拍脑袋） |
| `create_ticket_draft(...)` | 写操作：生成工单草稿 | **必须人工确认才落库**，AI 不直接建单 |

> 为什么不继续加：v1 说得对，工具越多越讲不清。4 个刚好覆盖"查知识 / 查历史 / 查现场 / 进流程"四类边界，且每类的失败模式都不同，面试时逐个讲得清。

## 3. 两类拒答（本项目最重要的一个设计）

| | `safety_blocked` | `insufficient_evidence` |
|---|---|---|
| 触发 | 规则命中：高压 / 带电 / 拆机 / 燃气 / 高温 / 防爆区作业 | 检索 top1 分数低于阈值；或问题里的实体（型号/零件号/规格）在知识库中不存在 |
| 执行 | **短路**：不查库、不调模型 | 已查库，说明查到什么、缺什么 |
| 回复 | "该问题须由持证人员处理，已生成工单草稿（P1/SLA 待定），转设备科" | "手册未收录 XX 型号的轴承规格；已检索到相关章节 2 处，建议查设备铭牌或转设备科" |
| 指标 | 拦截率（应 100%）、**误拦截率** | 拒答正确率、**误拒率** |

两者分开的意义：安全性是"不让 AI 碰"，证据是"AI 没有料"。混在一起的系统，面试官一问"你这个拒答到底是安全还是不会"就散了。

**引用校验是硬约束**：生成后逐条核对 `chunk_id` 是否真实存在且属于该型号，挂不上就整条降级为"低置信"，不允许"大概在某页"。

## 4. 数据策略

| 数据 | 规模 | 来源与标注 |
|---|---|---|
| 真实手册 | 1 本 | 公开可下载的工业设备说明书（空压机/泵），保留原始页码 |
| 自制手册 | 2 本 | 离心泵 / 换热器，Markdown→PDF 生成，含故障码表、表格、安全警告；化工现场细节（防爆区 Ex d IIB T4、LOTO 挂牌上锁、介质腐蚀、氮气置换） |
| 设备档案 | 6 台 | 型号 / 产线 / 位置 / 阈值 / 手册映射 |
| 历史工单 | 300 条 | 合成，README 标注 |
| 传感器 | 3 台 × 7 天 × 1min | 合成，含 3 段注入异常 |

README 首屏第一行固定为：

> **本仓库设备手册中的自制部分、全部工单与传感器数据均为合成示例；1 本真实手册为公开资料。不含任何真实工厂数据与企业信息。**

## 5. 评测口径

30 条样本，四类：

| 类别 | 条数 | 说明 |
|---|---|---|
| 故障码问答 | 10 | 标准单跳，gold 段落明确 |
| 操作步骤 | 8 | 需跨章节拼装（多跳） |
| 参数含义 | 5 | 短答案，考精确命中 |
| 应拒 | 7 | 细分：明显无关 2 / 相似但缺关键字段 3 / 安全性 2 |

输出指标：

```
检索      Recall@1 / Recall@3 / Recall@5 / MRR（chunk 级）
引用      引用精确率（引用的 chunk 是否都在 gold 集合内）/ 引用覆盖率（gold 是否被引全）
拒答      2×2 混淆矩阵（应答应拒 × 实答实拒）+ 拒答正确率 + 误拒率
安全      拦截率 + 误拦截率
型号过滤  A/B：关闭硬过滤后「引用到错误型号手册」的比例
延迟      p50 / p95（stub 下限 + real 实测两行，分开写）
```

每个数字附：commit、数据版本、样本数、运行时间、provider 模式。

## 6. 排期（今晚起，后天截止）

| 阶段 | 内容 | 交付 |
|---|---|---|
| **P0（今晚，≤40min）** | 风险探针：真实 PDF 能否抽出干净文本 + 页码 + 章节标题 | 一个能跑的小脚本 + 结论。抽不干净立刻走降级路径 |
| **P1（今晚）** | 骨架：FastAPI + stub provider + `/healthz` + 目录 + pytest 骨架 | `curl /healthz` 返回 `provider: stub` |
| **P2（今晚）** | 检索：章节切分 + bigram BM25 + 型号过滤 + `evals --stage retrieve` | 真跑出来的 Recall@1/3/5 |
| **P3（明天上午）** | 编排：4 工具 + 并行 + trace + stub 生成（带引用模板） | `/api/ask` 的 trace 里 4 条工具记录 |
| **P4（明天下午）** | 两闸：safety + evidence + citation 校验 | 应拒样本全部正确拒 |
| **P5（明天晚）** | 工单三态 + 单页前端（对话/证据面板/工单卡） | 点引用能高亮到原文 |
| **P6（后天上午）** | 30 条评测 + 报告 + README + 失败案例 | 控制台表 + JSON，pytest ≥15 绿 |
| 缓冲（后天下午） | 只修 bug、只补文档、录演示 | 三分钟演示跑顺 |

### 降级路径（按顺序触发，不犹豫）

1. 真实 PDF 抽不出 → 全自制 PDF，README 写明"未处理真实扫描件"
2. 向量模型下不下来 → 只用 BM25，报告里注明"向量分支未启用"，并给出 bigram BM25 的 Recall 作为基线
3. 时间吃紧 → 先砍 P5 前端（退到 `/docs` + curl），再砍工单写操作（退到只读历史工单）
4. LLM key 没有 → 全 stub，README 标注"stub 模式答复为模板拼装，不代表模型能力"

## 7. 验收（不写死目标值）

- [ ] 断网、无 key，stub 模式能完整跑完评测并出报告
- [ ] `pytest -q` ≥ 15 条全绿
- [ ] 每条答复带引用；无引用必须拒答（`safety_blocked` 或 `insufficient_evidence`）
- [ ] 报告里每个数字可追溯：commit / 数据版本 / 样本数 / 运行时间 / provider
- [ ] 型号过滤 A/B 两组数字都在报告里
- [ ] README 有「本 demo 不证明什么」一节
- [ ] 至少 3 条失败案例 + 原因分析

## 8. 三分钟演示

1. **0:00** 「3 号线空压机报 E05，排气温度 118℃，怎么处理？」
2. **0:40** 证据面板：手册 p87 段落 2 处 + 同型号历史工单 3 条 + 当前排气温度超阈值 → 处置步骤每条挂出处
3. **1:30** 「这台泵的轴承型号是多少？」→ `insufficient_evidence`：说清缺什么、建议查铭牌
4. **2:00** 「带电拆开接线盒检查」→ `safety_blocked`：不查库不调模型，直接转人工 + 工单草稿
5. **2:20** 打开评测报告：四类样本 + 混淆矩阵 + 型号过滤 A/B
6. **2:40** 收尾：「工业场景里，答错比不答贵得多。所以我做的不是让模型更会说话，是让它的话能追到页码，追不到就不说。」

## 9. 真实情况下的已知边界

- 工单、传感器、自制手册为合成数据
- 未接 MES / 设备网关，传感器为 CSV 回放
- 工单只到草稿态，无 SLA 计算、无审批流、无权限
- 并行工具调用的延迟收益在本地是毫秒级，演示时用可配置模拟延迟体现（README 标注"模拟"）
- 未做并发压测、未做多租户
